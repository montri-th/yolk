# แผนที่เดียว ค่อย ๆ เจาะจนเจอทำเล

เปิดภาพรวม ปรับเกณฑ์ เล็งทำเล หรือจัดการสาขา ใช้แผนที่เดียวตลอด ผู้ใช้เลื่อนและซูมค้างไว้ แล้วทำงานในแผงข้อมูลข้าง ๆ โดยไม่ต้องเปิดแผนที่ใหม่

Desktop ตั้งแต่ 1,100 px ให้แผนที่เป็นพื้นที่หลักและแผงข้อมูลด้านขวาเลื่อนแยกกัน บนจอแคบแผนที่ sticky ด้านบนและข้อมูลอยู่ด้านล่าง มุมมองคงอยู่ระหว่างใช้งานในหน้าที่โหลดนี้ ยังไม่บันทึก pan/zoom ข้าม reload

## ลำดับการสำรวจตามคำขอเจ้าของ

| กำลังดู | สีแบ่งตามพื้นที่ใด | เลือกเพื่อดูต่อ |
|---|---|---|
| ทั้งประเทศ | **อำเภอ** — สรุป Tier ยืนยันดีที่สุดของทำเลที่ผ่านในอำเภอนั้น | เข้าจังหวัดที่เลือก |
| จังหวัด | **ทำเลละเอียด** — แขวงใน กทม. / อปท. ต่างจังหวัด ตาม reporting UUID | เข้าอำเภอที่เป็น parent ของทำเลที่เลือก |
| อำเภอ | **ทำเลละเอียด** แบบเดิม จึงเทียบสีต่อเนื่องได้ | เลือกทำเลเดียว |
| ทำเลที่เลือก | Polygon ต้นทางเมื่อมี หรือ extent ที่ติดป้ายชัด | ดู **O สาขาเรา / C คู่แข่ง / U รอตรวจ** ที่มีพิกัดและความสัมพันธ์กับพื้นที่ที่ตรวจได้ |

```mermaid
flowchart LR
    C["ประเทศ
สีตามอำเภอ"] --> P["จังหวัด
สีตามทำเลละเอียด"]
    P --> D["อำเภอ
สีตามทำเลละเอียด"]
    D --> A["เลือกทำเล
ดู O / C / U"]
    A --> D
    D --> P
    P --> C
```

การเลือกจังหวัด/อำเภอเป็นการเปลี่ยนมุมมอง ไม่คำนวณเกณฑ์หรือ percentile ใหม่ อำเภอในภาพประเทศใช้ **Tier ยืนยันดีที่สุดจากทำเลละเอียดที่ผ่านและมี crosswalk สำหรับมุมมองพื้นที่ตรวจแล้ว** ไม่ใช่การประเมิน Demand ใหม่ทั้งอำเภอ ทำเลที่สัมพันธ์กับหลายอำเภออาจอยู่ในหลาย summary แต่ยอดรวมประเทศนับ reporting UUID ไม่ซ้ำ ไม่บวกจำนวนความสัมพันธ์แทนจำนวนทำเล

**ขอบเขตที่จัดหาได้:** native source projection มี 928 อำเภอและ 7,954 ทำเลละเอียดใน 77 ไฟล์จังหวัด ดู [hierarchy index](../prototype/data/real/hierarchy-index.json) ซึ่งบันทึก count/hash รายไฟล์ มี 7,909 ทำเลสัมพันธ์กับอำเภอเดียวและ45 ทำเลสัมพันธ์กับหลายอำเภอ ไม่มี UUID ที่ยังไม่เชื่อมใน projection นี้ การมีไฟล์ครบไม่แทน topology/model checks หรือ browser review และไม่รับรองรอบขอบเขต/เขตตามกฎหมาย จุดที่ข้อมูลโหลดไม่สำเร็จยังต้องแจ้งสถานะ ห้ามแทน grain อำเภอด้วยสีจังหวัดโดยเงียบ ๆ

**ที่มาของรูปขอบเขต:** ดู [boundary provenance](../prototype/data/real/boundary-provenance.v1.7.json) ต้นฉบับที่มี topology ผิดรูปถูกเตรียมเป็น display projection ด้วย `make_valid` โดยเก็บเฉพาะส่วน polygon และตัดเส้นที่ยุบเหลือพื้นที่ศูนย์: 6 อำเภอ, 47 แขวง และ 3,770 อปท. ต้นฉบับเก็บไว้ไม่แก้ ชุดแสดงผลลดจุดที่ tolerance 0.0006° สำหรับอำเภอ / 0.00015° สำหรับทำเล; หากผลลดจุดไม่ valid ให้ใช้ส่วนต้นทางที่ valid โดยไม่ลดจุด ขอบเขตแสดงผลทั้ง 8,882 polygons ผ่าน validity check ไม่มี bbox แทน polygon การเตรียมรูปนี้ไม่แก้ metric หรือตัวหารพื้นที่จาก `base.areaSqm` และไม่รับรองเขตกฎหมาย

Crosswalk ใช้สัดส่วนพื้นที่ polygon ทับซ้อนใน EPSG:4326 แบบ planar ≥ 0.5% ของทำเลเพื่อคัดเศษขอบ ไม่ใช่พื้นที่สำรวจภาคพื้นจริง เมื่อสัมพันธ์หลายอำเภอ ผู้ใช้เลือกอำเภอที่จะเจาะต่อ เช่น ทำเลแหลมฉบังสัมพันธ์กับศรีราชาและบางละมุง การเดาจากรหัสเทศบาลเพียงอย่างเดียวจึงใช้แทนไม่ได้

คำว่า “ทำเลละเอียด” ใช้ grain ที่มีข้อมูลจริง: กทม. ใช้แขวง ต่างจังหวัดใช้ อปท./เทศบาล การใช้ตำบลแบบ optional ต้องมี crosswalk เพิ่ม อปท. ไม่เท่ากับตำบลโดยอัตโนมัติ Polygon ที่มีจากต้นทางไม่ใช่การรับรองเขตกฎหมายอย่างอิสระ

## แต่ละเมนูใช้แผนที่อย่างไร

- **ภาพรวม:** hierarchy ตามตาราง พร้อมรายชื่อและอันดับทำเล
- **เล็งไว้:** เน้นทำเลที่บันทึกไว้ในบริบทแบรนด์/ขอบเขตนี้ รวมรายการที่ปัจจุบันไม่ผ่านเกณฑ์
- **สาขา / Supply:** คงระดับสำรวจ เมื่อเลือกทำเลละเอียดจึงเห็นหมุดตาม tab, แบรนด์, การค้นหา และตัวกรอง O/C/U
- **เกณฑ์:** คง hierarchy/zoom พร้อมผลแบบร่างและผลก่อนปรับ
- **รายละเอียดทำเล / สาขา:** การเปิดรายการใหม่เป็น explicit focus ไปยังบริบททำเลที่ตรวจ parent ได้ ฟอร์มเดิม render ซ้ำไม่ซูมกลับ
- **กิจกรรม / แจ้งเตือน:** แสดงบริบทตำแหน่งที่อ้างถึงในธุรกิจปัจจุบัน กิจกรรมที่ไม่มีพิกัดไม่สร้างหมุด การเปิดเหตุการณ์เรียกแบรนด์/scope ของเหตุการณ์นั้นกลับมา
- **ทีม:** คงแผนที่และบริบทปัจจุบันขณะจัดการสมาชิก

หมุด O/C/U แสดงเมื่อเลือกทำเลละเอียดแล้ว ไม่โปรยหมุดทั้งประเทศ ยอด Supply ในตารางและ POI เป็นคนละหลักฐาน จำนวนรวมไม่ถูกสร้างเป็นพิกัดจุด

## ลองเกณฑ์แล้วเห็นความต่าง

หน้าเกณฑ์ใช้ draft ที่ valid; หน้าอื่นใช้เกณฑ์ทีมที่บันทึกแล้ว เลือกมุมมองได้ **ผ่านเกณฑ์ / เกณฑ์ทีม / เข้าใหม่ / หลุดเกณฑ์ / รอตรวจ / อันดับเปลี่ยน** ใช้ชุด ID ก่อน–หลังจาก evaluator เดียวกัน การปรับน้ำหนักเปลี่ยนลำดับได้โดยไม่เปลี่ยนสมาชิกที่ผ่าน ส่วนค่าตัดและรูปแบบทำเลอาจเปลี่ยนสมาชิก

ลาก slider หรือกรอกตัวเลขในช่องคู่กัน หากช่องว่างหรือค่าผิด แผนที่พักคำนวณพร้อมข้อความและคงผลล่าสุดที่ใช้ได้ ไม่แสดง “0 ทำเล” เสมือนเป็นผลใหม่ **กด Apply จึงเปลี่ยนเกณฑ์ทีม** การเลื่อน ซูม drill/back หรือเปลี่ยนชั้นข้อมูลไม่สร้างกิจกรรมทีม

## อ่านสี เส้น และหมุด

สีข้อมูลคือ **Tier ยืนยันของไข่แดงที่ผ่านในมุมมองนี้** ใช้ native `li.demand` 3 classes ของ LDS 0.9.7 ทั้งสองธีม:

| Tier | Native class | HEX | ความหมาย |
|---|---:|---|---|
| Tier 1 | 3 | `#25659A` | ผ่านเกณฑ์ Demand ระดับที่เข้มที่สุดของ preset นี้ |
| Tier 2 | 2 | `#60C9AD` | ผ่านระดับถัดมา |
| Tier 3 | 1 | `#F1F5E5` | ผ่านเกณฑ์เริ่มต้น |

คงสีเดิมและ fill opacity 1 บน light/dark สีไม่ใช่ percentile ของ polygon, rank score, จำนวนลูกค้า หรือผลธุรกิจ พื้นที่ไม่มีผลผ่านยืนยันใช้พื้นกลาง ส่วน missing/review มีข้อความ/เส้นประ/จำนวนแยก สีอ่อนไม่ได้พิสูจน์ว่า Demand เป็น 0

เมื่อเลือกทำเลละเอียดแล้ว ใช้ขอบเขตแบบ **ไม่เติมสี (`fill=false`)** เพื่อให้เห็นถนนและภูมิประเทศ เน้นเส้นขอบ ชื่อ และ Tier/status การเลือกนี้เป็น selection outline; quantitative choropleth ในประเทศ/จังหวัด/อำเภอยังคง exact fill opacity 1 ไม่ทำสีข้อมูลโปร่งหรือแปลงสีตามธีม

- **เส้นทึบ:** Polygon/MultiPolygon ที่ต้นทางส่งมาและติด source/verified
- **เส้นประไม่เติมสี:** source extent ใช้จัดมุมมอง ไม่ใช่ขอบเขตพื้นที่หรือ spatial join
- **O:** Our stores / สาขาเรา
- **C:** Competitors / คู่แข่ง
- **U:** Unverified / รอตรวจ ไม่ใช่ข้อยืนยันว่าสถานี unbranded หรือสาขามีผลิตภัณฑ์/ใบอนุญาตใด
- **จำนวนรอตรวจ:** สรุปรายการที่ยังไม่แน่ชัด ไม่ใช่พิกัดสาขา

POI ใช้พิกัดต้นทางหรือ draft ที่บันทึกจริง พร้อมสถานะการผูก reporting UUID ไม่ใช้ชื่อ ตำบล bbox หรือการมองเห็นใน viewport ยืนยันว่าจุดอยู่ในเขตทางกฎหมาย ฐานเปรียบเทียบคงประเทศ 7,954 UUID เหมือนเดิม

จุดที่ยังไม่ผูก reporting UUID อาจแสดงเมื่อพิกัดจริงอยู่ใน source display polygon ของทำเลที่เลือก เป็น **view-only** ไม่เขียน UUID กลับ ไม่จัดสรรยอด Supply และไม่รับรองเขตปกครอง Editor อาจ focus พิกัดสาขาเดี่ยวที่ยังไม่ทราบ boundary พร้อมป้ายตรงไปตรงมา ไม่สร้างทำเลสมมติ

## แผนที่พื้นหลัง

**Simplified** และ **Detailed** ใช้ OpenStreetMap; Simplified ลดความเด่นของ tile pane เท่านั้น **Satellite** เป็น ESA WorldCover/Copernicus Sentinel-2 ปี 2021, 10 m ผ่าน Terrascope ใช้ประกอบบริบท ไม่ใช่ภาพปัจจุบันหรือหลักฐานรายแปลง ซูมเหนือ native 14 ไม่เพิ่มรายละเอียดจริง

เปลี่ยนพื้นหลังแล้วคง instance/ตำแหน่ง/zoom ดู attribution ในแผนที่: [OpenStreetMap](https://www.openstreetmap.org/copyright), [Terrascope](https://docs.terrascope.be/Developers/WebServices/OGC/WMTSv2.html), [geoBoundaries](https://www.geoboundaries.org/) ต้องระบุแหล่งของ geometry เพิ่มตามที่จัดหาได้จริง

## คงงานที่กำลังทำ และบอกข้อมูลที่ยังไม่พร้อม

Map host อยู่นอก `#content` เรียก `mount()` ซ้ำแล้วใช้ instance เดิม `sync()` ไม่ refit การซูม/เปลี่ยน hierarchy เกิดจาก explicit action เท่านั้น เมื่อ render ฟอร์มเดิมใน route hash/context เดิม เก็บค่า select/text, province selector, cursor และ focus คืน ร่างรูปอยู่ใน photo module แยก ไม่ reconstruct file input และไม่ถ่ายร่างให้อีกสาขา/แบรนด์

Async focus จับ ticket + context + route ก่อน await แล้วตรวจอีกครั้ง ถ้าผู้ใช้เปลี่ยนงาน/แบรนด์ ลากแผนที่ หรือเลือกจุดใหม่ คำขอเก่าต้องไม่ดึงแผนที่กลับ

การ save สาขาที่รอประมวลผลรูปจับ context/route/record/revision ไว้และตรวจซ้ำหลัง await ถ้าผู้ใช้เปลี่ยนบริบท ผลเก่าต้องยกเลิกโดยไม่แก้หรือ rollback POIs ปัจจุบัน ไม่สร้าง event ข้ามบริบท

แสดงสูงสุด 1,000 หมุดและ 350 ทำเลต่อมุมมอง พร้อมจำนวนที่แสดงเทียบรายการ เป็นเพดาน render ไม่ใช่จำนวนฐานทั้งหมด ถ้าธุรกิจโหลดไม่สำเร็จ ซ่อนผลเก่า; geometry/crosswalk ยังไม่มีให้ติดสถานะ; POI/tile โหลดไม่ได้ไม่ตีความเป็นศูนย์ ชั้นหลักฐานอื่นที่มีพร้อมยังใช้งานได้

## เริ่มพัฒนาต่อ

อ่าน [machine contract](../contracts/workspace-map.v1.7.json) และ [Implementation plan](../IMPLEMENTATION_PLAN_v1.7.md) งานแผนที่มี 6 ขั้น: **mount ครั้งเดียว → sync ไม่ refit → explicit drill/focus → guard invalid/loading/error → buffer ฟอร์ม → QA**

API hierarchy คือ `navigate(path,{fit:true,notify:true})`, `back()`, `getNavigation()`, `areaMatchesNavigation(areaOrId)`, `poiMatchesNavigation(p)`, `navigationLabel()` และ callback `onNavigate(path)`; `path.level` คือ `country/province/district/location` พร้อม source `provinceCode/districtId/areaId` ที่เกี่ยวข้อง ไม่ใช้ชื่อเป็น identity join ตัวอย่าง: `navigate({level:"province",provinceCode:"10"},{fit:true,notify:true})`

รัน `node scripts/check-workspace-map.cjs` และ model/brand/photos regression แล้วตรวจ browser จริง TH/EN light/dark บน mobile/desktop ทุกระดับและเมนู รวม popup, keyboard/touch, ฟอร์มค้าง, invalid draft และ provider failure Model/DOM-adapter tests ไม่พิสูจน์ความอ่านง่ายหรือ pan/touch จริง แนบ receipt ของ release; แผนที่ช่วยคัดไปศึกษาต่อ ไม่ยืนยันยอดขาย ผู้กู้ หรือความเป็นไปได้ของที่ดิน
